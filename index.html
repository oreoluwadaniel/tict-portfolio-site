Project 1

Operations Command Dashboard

Power BIDAXPower Query

A multi-page Power BI report that gives an operations manager one place to see where time and money are being lost.

The problem

Performance information sat in separate files, so nobody could see the whole picture quickly. Delays and growing charges were noticed late, after the answer had already been put together by hand.

What it shows

  • Where waiting time builds up and which partners drive it
  • Which areas are holding items longest and costing the most
  • Which few items deserve attention first each morning

What I built

  • An overview page with headline cards, trends, a league table and the items most worth chasing
  • Pages that break delays down by partner, location and time of day
  • A detail page that opens a single job and compares it with the average
  • Time window controls and filters so each manager can focus on their own area
  • Every figure checked against a separate calculation outside Power BI

Project 2

IT Support and Equipment Reliability

Power BIPostgreSQLSQLDAX

A database layer and multi-page report that shows where IT delays and equipment breakdowns cost the business most, and which repeat support work to automate first.

The problem

IT and engineering managers needed to know where to add support cover, which machines need a review and which routine tickets are worth automating. The raw logs could not answer any of that.

What it shows

  • Which ticket types and shifts miss their response targets
  • Which fault types and machines account for most downtime
  • Which routine tickets are the best candidates for automation

What I built

  • A PostgreSQL database holding ticket, breakdown and data-transfer logs, with built-in checks and a read-only login for reporting
  • An overview page, an IT support page, an equipment page, an automation page and a one-machine case file
  • Downtime counted correctly when events overlap on the same machine
  • Estimates of the time routine ticket types could save if automated

Project 3

Daily Operations Automation

Power AutomateExcelHTML email

Power Automate flows that run the daily routine, so the report, the alert and the data check are done before the manager sits down.

The problem

Each morning someone opened several spreadsheets to see how yesterday went, which items were costing money and whether the data was complete. It took time and was skipped on busy days.

What it shows

  • Reports and alerts arrive on schedule without anyone building them
  • Problems are caught and flagged instead of passing silently
  • Run history is visible in Power Automate for every flow

What I built

  • A data check that confirms the day's data exists and sends a failure email with the failed step and a link to the run
  • An alert that lists the costliest items, sent once and marked so nothing is reported twice
  • A designed email report comparing yesterday with the recent average
  • Settings such as report date, alert limit and recipient kept in a table, so changes need no flow edits
  • Every failure written to a run log with its error message

Project 4

Charge Waiver Approval System

Power AppsSharePointPower AutomatePower Automate Desktop

A request, approval and posting process for charge waivers, built from the request form through to the billing screen.

The problem

When a delay is not the customer's fault, a clerk can waive part of a charge, but only with approval. Many businesses run this through email chains and re-typing into an older billing screen, which causes errors and delays.

What it shows

  • Requests move from form to approval to posting without re-typing
  • Bad entries are stopped with a clear error code
  • Re-running the robot does not create duplicate postings

What I built

  • A Power Apps request form that works out the charge live as the requester fills it in
  • SharePoint lists holding requests and the lookup data
  • An approval flow that routes requests by amount, records the decision and emails the requester
  • A desktop robot that enters approved waivers into the billing screen, retries when it is busy and logs every result
  • Business rules enforced in the app and on the billing screen
